Testing a local LLM for product analytics.

On two projects, a locally hosted Llama 3 model answers questions about product analytics. An answer that sounds confident but gets a number or a trend wrong is worse than no answer. So I wrote 100 prompts from the domain, worked out the correct answer for each from the data, and validated every model answer by hand in a table.

Illustrative replay. The model is a locally hosted Llama 3. The project is under NDA, so the prompts, data and results shown here are representative examples of the method, not the real ones.

How I work

        

      

      
    
        
  1. 01
    Write the prompts
    100 questions a product team actually asks about its analytics, plus the ones nobody asks on purpose: empty periods, missing fields, odd date ranges, instructions hidden in user text.
    2. 
        
  2. 02
    Work out the right answer
    For every prompt I take the correct answer from the data itself, before asking the model. The model is judged against the data, not against what sounds reasonable.
    3. 
        
  3. 03
    Grade every answer
    Each answer gets a row in the table: correct, consistent with related prompts, safe. A short note explains every partial or wrong grade.
    4. 
        
  4. 04
    Report and re-check
    Wrong and partial answers go to the team with the table row as evidence. After a change to the model or the prompt template, I run the affected prompts again.
